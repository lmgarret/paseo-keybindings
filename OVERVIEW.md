Remaps keyboard shortcuts in the Paseo desktop and web app. Each binding is a key, a command, and an optional `when` clause such as `!terminalFocus && hasSelection`, so the same key can act differently in the terminal and in chat.

No bindings are active until you add them. A typical one makes Ctrl+C copy selected text in chat, the composer, and agent output, while Ctrl+C in a focused terminal still interrupts the running process. This suits macOS setups that emulate Windows or Linux shortcuts with a tool like Karabiner-Elements, which cannot tell which pane has focus.

Keys without a matching binding behave exactly as before. Commands and contexts use VS Code names, and VS Code command ids work too. Other commands cover cut, paste, select all, undo, redo, typing text, word, line and document movement, deleting, duplicating and moving lines in text inputs, plus copying, pasting and sending text in the focused terminal. Your bindings live in keybindings.json in the Paseo home folder on the daemon host and apply as soon as they change. Edit them from the Command Center: Preferences: Open Keyboard Shortcuts opens a searchable table with a key recorder, and Preferences: Open Keyboard Shortcuts (JSON) opens a JSON editor with highlighting, validation, and completion.

The plugin only listens to keyboard events inside the app. Its daemon side only reads, writes, and watches keybindings.json. It sends nothing anywhere else. Shortcuts only apply on desktop and web; on iOS and Android you can still edit the file. Paseo's own shortcuts live in the same file: every Paseo action is a command, so you can bind more keys to it, give it a when clause, or move it to another key, as in VS Code. The table lists Paseo's shortcuts next to the plugin's, including rebinds made in Paseo's settings, and your bindings take precedence over Paseo's on the same key. Keys taken by the desktop app menu never reach the plugin.
